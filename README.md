# 길동무

> 막힌 길에서 근처 차에게 묻고 알리고 도움받는 차량용 앱. 덤으로 **가는 길 가게도 말로 물어 주문·결제**할 수 있습니다.

현대·기아 **차량용 앱 개발 공모전**(Pleos App Market)에 참가하려고 만든 프로토타입입니다. 개인 참가(대학(원)생 부문).
**처음 보는 팀원은 [docs/ONBOARDING.md](docs/ONBOARDING.md)부터 읽으세요**(읽는 순서, 실행 명령, 파일 지도).
화면 캡처는 최종 시연 영상을 다시 찍을 때 이 자리에 넣을 예정입니다(예전 캡처는 지금 디자인과 달라서 뺐습니다).

## 주 기능과 부가 기능
| | 무엇을 | 어떻게 (자세한 흐름은 아래와 docs) |
|---|---|---|
| **주 기능: 막힌 길 소통·신고** | 정체·사고·낙하물 같은 현장 사정을 바로 앞 이웃에게 묻고 답을 받음 | "왜 막혀요?" 한 번 또는 말로 → 실제 접속한 이웃만 300m 안에서 답 → "도움이 됐어요" |
| **부가 기능: 음성으로 가게 찾고 결제** | 말로 가까운 가게를 묻고, 메뉴·가격을 듣고, 결제까지 | 말 "근처 해뜰커피 있나?" → 가장 가까운 곳과 메뉴를 읽어 줌 → "샌드위치 얼마야?" → "결제해줘" → 가게 화면에 주문 → 조리·준비·수령 진행을 앱이 따라감, 막히면 도착 시간이 늦춰져 가게에 전달 |

픽업·결제의 가게 연동·결제 구조 설명은 [docs/PICKUP_PAYMENT.md](docs/PICKUP_PAYMENT.md), 전체 구조는 [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md), 팀 역할은 [docs/TEAM.md](docs/TEAM.md)에 있습니다. **가게 데이터·결제는 샘플·모의이고, 실제 결제·가게 전달은 없습니다.**

## 폰 주문 앱과 무엇이 다른가 (차 안에서만 되는 것)
| 폰 앱 | 길동무 |
|---|---|
| 운전 중에는 쓰면 위험하고, 쓰려면 폰을 열어야 시작 | **말로 시작해 말로 끝납니다.** 마이크 버튼 한 번 누르고 "근처 스타벅스 알려줘" → 메뉴·가격 → "결제" → 결제창 확인, 손 안 대고 이어짐 |
| 가게까지 직선거리로 도착 시간을 추정 | **차의 내비게이션 길로 계산합니다.** 주문한 가게를 내비 **경유지로 넣고**(차 내비에 실제 전달 확인), 내비가 알려 주는 길 시간(예: 직선 3분이 실제로 22분)을 가게 화면에 보내 "막혀서 +19분"으로 조리 시작을 미룹니다 |
| 메뉴 고르기·글자 입력 | 주행 중에는 터치 없이 **말 세 마디**, 고민 없는 간단한 메뉴 하나만 제안 |
| 기어·속도를 모름 | 차가 기어(Pleos Vehicle SDK)와 속도로 주행/정차를 알아서 터치를 막고 음성으로 바꿈 |

**말로 하는 흐름:** "근처 주유소에 파는 거 알려줘" → 가장 가까운 주유소 편의점이 열리고 "생수, 샌드위치, 초코바를 팔아요"라고 읽어 줌 → "샌드위치 얼마야?" → "3,800원이에요. 결제할까요?" → "결제해줘" → 접수번호. 가게 이름("근처 해뜰커피 알려줘")으로도 됩니다.

**가게 데이터의 들고 나기:** 가게(서비스에 등록한 상점)의 데이터는 차가 **5km 안에 들어올 때** 받고, **6km 밖으로 멀어지면 차에서 지웁니다**(5~6km 사이는 유지해서 경계에서 깜빡이지 않게 함). 디스크에는 저장하지 않고 앱을 끄면 비워집니다. 에뮬레이터에서 차를 55km 옮기자 가게 5곳이 지워지는 것을 확인했습니다. 주문한 건은 접수번호로 계속 따라갑니다.

※ 결제·가게는 샘플·모의이고, 말 세 마디가 실제로 몇 초인지는 마이크로 재 보지 못했습니다(에뮬레이터에 인식기가 없음).

## 왜 만들었나
명절에 고속도로에서 차가 서 버리면 앞에서 무슨 일이 있는지, 휴게소가 붐비는지 알 방법이 없습니다.
내비는 "사고가 있음", "휴게소가 여기 있음"까지만 알려 줍니다. 하지만 **"한 대 정리 중이라 곧 풀려요", "주차장이 만차예요"** 같은 현장 사정은 바로 앞에 있는 사람들이 압니다.
그래서 근처 차끼리 물어보고 답할 수 있게 만들었고, **한 사람이 답하면 그 정보가 근처 모든 차에 쌓이도록** 했습니다.

## 핵심 기능
- **내비 안내 줄:** 도로 화면 맨 위에 다음 회전(방향·거리·방면)과 도착 시각·남은 시간·거리가 고정으로 나옵니다. 도로 위에 겹치지 않습니다. (Pleos NaviHelper의 TBT 정보, 조회 전용)
- **도로 화면:** 위에서 내려다본 평평한 도로에 내 차(흰색)와 앱을 쓰는 이웃(파랑)이 나오고, 모두 이름표가 있습니다. 도로가 꽉 차도 말하는 차와 답한 차는 먼저 올라옵니다.
- **내 프로필:** 헤더의 아바타·닉네임을 누르면 이름(목록에서 뽑기)·색·현대 차종(12개)·차종 공개 여부를 고릅니다. 글자를 입력하는 곳은 없고, 바꾸는 즉시 저장됩니다.
- **물어보기:** "왜 막혀요?"는 한 번 터치나 음성으로 묻습니다. 그 밖의 질문은 **말로** 하고, 읽어 준 글을 확인한 뒤 보냅니다. 전체 이웃에게 묻거나, 도로의 **차를 눌러 그 차에게만** 물을 수 있습니다(같은 차에는 1분에 한 번).
- **알리기:** 사고·낙하물·로드킬·공사 중. 낙하물과 로드킬은 "촬영하고 신고"를 눌러야 사진 한 장과 위치로 접수되고, 접수번호가 나옵니다.
- **가는 길 픽업 (샘플 데이터·모의 결제):** 가게가 **서버에 스스로 등록**하고(이름·브랜드·종류·위치·전화번호·준비 시간·메뉴 구조, `POST /api/shops/register`), 차가 가까워지면 앱이 차의 위치로 **5km 안 가게**를 받아 옵니다. 고르는 기준은 장소가 아니라 **받고 싶은 것**(커피·음료, 식사, 간식)이라 드라이브스루·휴게소 식당·편의점에 똑같이 쓰이고, 범위 안에 없는 종류는 버튼이 나오지 않으며 하나도 없으면 "5km 안에 받을 수 있는 곳이 없어요"와 가장 가까운 곳의 거리를 알려 줍니다. 종류를 누르거나 "커피 마시고 싶어", "앞에 드라이브스루 뭐 있어?"라고 말하면 **가장 가까운 한 곳과 메뉴 하나**가 나와 고를 것이 없고(메뉴·가격은 "메뉴"라고 하면 읽어 줌), "결제"(또는 결제하기 버튼)로 접수번호를 받습니다. 도착 시간을 계산해 "N분 뒤 조리 시작"을 안내하고, 마음에 안 들면 "다른 곳"입니다. 가게 이름 옆 ♡를 누르거나 "단골"이라고 하면 그 **브랜드를 단골로** 저장해서 이후에는 단골 가게만 나옵니다("전체 보기"로 되돌림). 주문은 서버에 기록되고(`server/data/shops.db`), 가게 화면(`/shop`)에서 **수락 → 조리 시작 → 준비 완료 → 수령**으로 진행시키면 앱이 상태를 따라가며 음성으로 알려 줍니다. 차가 막혀 멀어지면 서버가 도착 시간을 다시 계산해 가게 화면에 "막혀서 +N분"을 보여 주고, 결제한 주문은 바로 조리에 들어가므로 앱에서 취소·환불하지 않습니다(문의는 가게 전화). 같은 가게의 다른 메뉴는 터치 한 번 또는 "크로와상으로"처럼 말로 바꿀 수 있습니다. 결제 수단은 **미리 한 번(정차 중) 등록**하고 차에는 카드 번호가 아니라 토큰만 남기는 구조입니다(지금은 모의 등록, `docs/PICKUP_PAYMENT.md`). **가게·거리·가격·전화번호는 모두 지어낸 샘플이고 결제는 모의라 실제로 청구되지 않으며 가게에 주문이 전달되지는 않습니다.** 실제로 쓰려면 매장 시스템·결제사와의 제휴와 가게 로그인이 필요합니다. 방향은 보지 않고 거리만 봅니다. **주행 중에는 버튼 대신 "운전 중이에요 · 말로 해 보세요"와 지금 가능한 종류만 보이고, 모든 것을 말로 합니다. 프로필(차종·이름)도 주행 중에는 터치 대신 "내 차는 아반떼", "이름 바꿔 줘"라고 말로 바꿉니다.**
- **도로 게시판과 점수:** 이웃이 올린 제보에 "맞아요 / 고마워요 / 덕분에 잘 지나갔어요"를 누르면 올린 사람이 점수를 받고 등급이 오릅니다(새싹 → 길잡이 → 도로 박사 → 도로 영웅). 확인 줄은 몇 초 뒤 사라지지만 제보 줄의 "확인하기"로 다시 열 수 있습니다.
- **신고와 차단:** 차를 누르거나, 이웃의 답·말·질문의 "신고"를 누르면 **이유를 고릅니다**(난폭 운전, 욕설·비하, 이상한 질문, 광고·스팸, 허위 제보, 기타). 신고하면 그 이웃은 차단되고 올린 글과 질문이 사라집니다.
- **디자인:** 낮/밤 테마(헤더에서 선택). 낮은 밝은 캔버스에 흰 카드(16px 라운드, 1px 테두리), 현대 남색(#002C5F)과 하늘색 포인트, 밝은 도로에 점선 차선, 이웃 차는 남색·내 차는 흰색. 밤은 어두운 도로. 글꼴은 Pretendard, 작은 글씨는 운전 중에 읽히도록 키우고 대비를 높였습니다.

### 주행 상태와 터치 정책
주행 중에는 **음성**, **한눈에 보이는 정보**(시선 2초 이내), **큰 버튼 한 번으로 끝나는 조작**만 둡니다.

| 상태 | 앱의 동작 |
|---|---|
| 주행 중 | 프로필 편집, 차 선택(한 대에게 묻기), 신고 이유 고르기, 가는 길 픽업 터치는 막습니다(픽업은 말로). 큰 타일 한 번 터치와 음성은 됩니다. |
| 정차(주차·정체로 서 있음) | 모두 됩니다. |
| 차량이 전면 제한(0x1FF)을 알림 | 터치 질문을 접고 **큰 음성 질문 화면**만 보여 줍니다. 서버도 터치 질문을 거절합니다. |

※ 에뮬레이터 측정에서 "정체로 서 있음(D단·0km/h)"은 설정 화면 금지 플래그(0x40)가 켜진 상태였습니다. 프로필 편집을 정차 중에 허용한 것은 이 앱의 판단이며, 심사에서 문제가 되면 `MainActivity.profileEditable()` 한 줄만 조이면 됩니다.

입력창·동영상이 없고, 주행 중에도 쓸 수 있는 앱(`distractionOptimized`)으로 선언했습니다.

## 실제로 연동한 것 / 아직 아닌 것
| | 상태 |
|---|---|
| Pleos **NaviHelper** (목적지, 남은 시간, 다음 회전, 위치) | 연동함. 에뮬레이터 내비의 실제 경로로 확인 |
| 차량 주행 상태, 속도 (AAOS 표준 Car API) | 연동함 |
| Pleos **Vehicle SDK** (기어, 브레이크 페달, 조회 전용) | 연동함. 에뮬레이터에서 기어 P·브레이크 false를 실제로 읽어 서버 전송 때 쓰는 기어로 사용. **기어를 바꿨을 때의 변경 이벤트는 가상 콘솔이 비활성이라 확인하지 못함** |
| Pleos **FusedLocation SDK** | 연동 코드와 권한 요청 있음(동의 후). 에뮬레이터에서 지원·권한 허용은 확인했지만 **위치 값은 오지 않아** 내비 위치와 GPS로 자동 대체됨 |
| Pleos **TextToSpeech·SpeechToText SDK** | 연동하지 않음(서버 등록 키가 필요하고 콘솔에서 "준비 중"이었음). 지금은 안드로이드 기본 음성 인식·TTS |
| 서버 (근처 차량, 질문, 제보, 신고, 프로필) | 직접 만든 Python 서버, 자동 테스트 114개 |
| 이웃 | **실제로 접속한 이웃만** 도로에 나옵니다(만든 가짜 차량은 없음). 시험은 폰 브라우저 이웃(`/neighbor`)과 시험 스크립트로 했습니다 |
| 휴게소, 맛집 정보 | 샘플 데이터. 공공데이터포털 API로 바꿀 예정 |
| 음성 | 안드로이드 음성 인식과 TTS. **에뮬레이터에는 음성 인식이 없어서 앱 안의 마이크 흐름은 에뮬레이터에서 확인하지 못함.** 질문 API는 직접 호출해서 확인. Pleos STT/TTS SDK는 콘솔에서 "준비 중" |
| 사진 | 표준 Camera2로 한 장. 차량 카메라를 서드파티 앱이 쓸 수 있는지는 문서에서 확인하지 못함(에뮬레이터 카메라에서만 확인) |
| 가는 길 픽업: 내비 경유지 연동(주문한 가게를 차 내비 경로에 넣고 길 시간을 받음) | 에뮬레이터에서 경유지 요청이 내비 앱에 전달되고 길 기준 시간이 돌아오는 것을 확인 |
| 가는 길 픽업 (가게 등록·조회, 주문, 결제) | 가게 등록·조회·주문 기록은 서버에 **실제로 구현**(자동 테스트 포함). 가게 데이터는 샘플, 결제는 모의, 가게에 주문 전달·지문 인증은 없음. 음성 주문은 에뮬레이터에 음성 인식이 없어 확인하지 못함 |
| 도로 관리 기관 전달 | **없음.** "접수됨"은 이 서비스가 받았다는 뜻입니다 |
| 진짜 Pleos 차량, 여러 대 동시 사용 | 시험하지 못함 |

## 서버에 어떻게 저장되나
| 데이터 | 저장 방식 |
|---|---|
| 위험 신고(접수번호, 위치, 본 시각·받은 시각, 사진) | **디스크.** `server/data/tickets.db`(SQLite, WAL)와 `server/data/photos/`. 서버를 다시 켜도 남습니다. 사진은 **30일 뒤 삭제**, 접수 기록은 유지 |
| 같은 신고를 다시 보낸 경우 | 앱이 신고마다 고유 번호를 보내서 같은 접수로 처리(응답이 늦어도 중복되지 않음) |
| 게시판 제보, 질문, 말풍선, 점수, 신고·차단, 프로필 | **메모리.** 서버를 다시 켜면 사라집니다(제보는 어차피 15분 뒤 사라짐) |

전송은 평문 HTTP(JSON)이고 인증이 없습니다. 시험 서버(내 PC)용이며, 실제 서비스라면 TLS와 차량별 인증이 먼저 필요합니다.

## 실행 방법
### 1) 서버
Python 3.12 이상, 설치할 패키지 없음.
```
python server/app_server.py 8080
```
에뮬레이터에서는 `10.0.2.2:8080`으로 접속합니다. **서버가 꺼져 있으면 앱 헤더에 "● 연결 끊김"이 뜨고, 질문·신고를 보낼 때 "연결을 확인해 주세요"라고 알려 줍니다. 가짜 답을 지어내지 않습니다.**
저장 위치는 환경변수 `GILDONGMU_DATA`로 바꿀 수 있습니다.
같은 Wi-Fi의 폰에서 시험 이웃 화면으로 들어갈 수 있습니다.
- `http://<PC주소>:8080/neighbor` : 이웃 화면(시험용). 프로필을 고르고 "이웃으로 참여"하면 질문이 오고 버튼으로 답합니다.
- `https://<PC주소>:8443/neighbor` : 같은 화면에서 말로 답하기(자체 인증서, 경고가 한 번 뜹니다).
- `http://localhost:8080/ask` : PC에서 말로 질문 변환 시험.

### 2) 앱
Pleos Connect 에뮬레이터(API 34)에 설치합니다.
```
adb install -r "apk/이정준_길동무_release.apk"
adb shell am start -n com.gildongmu.app/.MainActivity
```
첫 실행에는 **기능 소개 → 개인정보 안내(동의) → 프로필 설정(이름·색·차종, 건너뛰기 가능)** 순서로 나오고, 동의하기 전에는 위치·서버 연결을 시작하지 않습니다(차량 속도 권한 창만 그보다 먼저 뜹니다). Android Studio에서 열어서 실행해도 됩니다(`local.properties`에 `sdk.dir` 필요).

**테스트 환경:** Pleos Connect 에뮬레이터(Android 14, API 34), Android Studio의 JDK 17 이상, Gradle 8 이상, 서버는 Python 3.12. APK 위치는 `apk/이정준_길동무_release.apk`입니다. 필요한 퍼미션은 `docs/PERMISSIONS.md`에 있습니다.

**컴퓨터 두 대로 이웃 시험:** 한 대에서 서버를 켜고(방화벽 8080 허용), 다른 컴퓨터의 에뮬레이터에서 `adb shell am start --user 10 -n com.gildongmu.app/.MainActivity --es server http://<서버 PC 주소>:8080`로 시작합니다. 주소는 기억됩니다. 서버가 시험용이라 같은 와이파이 안에서만 쓰세요. **이 방법으로 두 대를 실제로 시험해 보지는 못했습니다.**

**디버그 빌드 전용 시험 옵션** (release APK에서는 무시됩니다):
- 위치 지정: `--ef fake_lat 37.9 --ef fake_lon 127.5` (내비게이션이 에뮬레이터 GPS를 덮어써서 `adb emu geo fix`로는 위치가 바뀌지 않습니다. 가는 길 픽업의 5km 범위를 시험할 때 씁니다)
- 주행 상태: `--es force_state moving|idling|locked`
- 음성 대신 글자 넣기: `--es say "'커피 마시고 싶어,메뉴,결제'"` (쉼표로 여러 문장, 4초 간격). 마이크 인식만 건너뛰고 해석 → 가게 읽어 주기 → 결제 → 서버 기록까지 시험합니다.

**가게 화면:** 서버를 켜고 `http://<PC주소>:8080/shop`을 열면 가게를 고르고 차에서 들어온 주문을 실시간으로 볼 수 있고, 가게가 스스로 등록하는 폼도 있습니다(시험용, 로그인 없음).

**이웃 시험 결과:** 에뮬레이터 앱 한 대와 `tools/neighbor_demo.py`(폰 이웃과 같은 서버 API를 쓰는 별도 클라이언트)로 시험했습니다. 이웃이 80m 앞에 파랑 차로 나타나고 말풍선과 도로 소식에 올라오며, 앱에서 "왜 막혀요?"를 보내면 이웃이 답하고 "도움이 됐어요"로 이어지는 것을 확인했습니다. **에뮬레이터 두 대(컴퓨터 두 대)나 실제 폰 이웃으로는 아직 해 보지 못했습니다.**

### 3) 주행 상태 바꿔 보기
Pleos Virtual Console(`adb forward tcp:8088 tcp:8088` 후 `127.0.0.1:8088`)에서 기어를 D로 두고 ACCEL을 누르면 속도가 올라가 주행 화면으로 바뀝니다. `tools/car.ps1`로도 바꿀 수 있습니다.
이 에뮬레이터는 앱을 **사용자 10번**으로 실행하므로, 앱 데이터를 지울 때는 `adb shell pm clear --user 10 com.gildongmu.app`을 써야 합니다.

## 개인정보와 안전
- 첫 실행에 위치·사진·음성·이름과 차종·신고가 어떻게 쓰이는지 알리고 동의를 받습니다(프로필 카드에서 다시 볼 수 있음). 권한 목록과 목적은 [docs/PERMISSIONS.md](docs/PERMISSIONS.md). 시연 순서는 [docs/DEMO.md](docs/DEMO.md).
- 위치는 거리 계산과 신고 위치에만 쓰고, 이웃에게는 정확한 좌표 대신 대략의 거리만 보입니다.
- 사진은 운전자가 "촬영하고 신고"를 누른 경우에만 한 장을 찍고, 계속 녹화하지 않으며 서버에서 30일 뒤 지웁니다.
- 말한 소리는 글자로만 바꾸고 저장하지 않습니다. 글자는 운전자가 확인하고 보내기 전에는 아무에게도 가지 않습니다.
- 이름·차종·신고 이유는 **정해진 목록에서 고르기만** 하고, 질문과 말에는 링크와 전화번호를 막습니다. 신고하면 차단됩니다.

## 한계와 앞으로
- **반경이 300m로 고정**입니다. 앱 보급률이 낮을 때는 주변에 쓰는 사람이 없을 수 있어서, 최소 인원을 채울 때까지 앞쪽 3km·뒤쪽 300m로 넓히는 방식을 검토 중입니다(`docs/`에 계산 근거 정리 예정).
- 이웃이 실제 차량 여러 대로 시험되지 않았습니다. 실제 서비스라면 위치 수집 동의와 비식별 처리가 먼저 필요합니다.
- 공공데이터(공사 현황, 휴게소 혼잡도) 실제 연동, 제휴 식당 쿠폰은 다음 작업입니다.
- 음성은 안드로이드 인식에 의존합니다. 정확도를 높이려고 오픈소스 Whisper를 서버에서 쓰는 방안을 측정해 봤고(큰 모델은 "내비"를 "넵"으로 들은 것 한 곳만 틀림), 앱에는 아직 연결하지 않았습니다.
- 서버 인증·TLS, 신고의 처리 상태(확인 중·전달됨) 기록은 아직 없습니다.
